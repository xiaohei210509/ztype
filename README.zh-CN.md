# ztype

**免费、开源的 Cotypist 平替，专为 Mac 打造。**

独立开发的 macOS 本地输入补全原型。应用标识为 `app.ztype.mac`，不读取、
迁移或复用其他补全软件的代码、设置、模型目录或授权。
ztype 与 Cotypist 无关联，不代表功能或应用兼容性完全一致。

[English](README.md)

## 下载与安装

在本仓库的 [Releases](../../releases/latest) 页面下载
`ztype-0.1.0-arm64.dmg`。支持 Apple Silicon Mac，要求 macOS 14 或更高版本。
DMG 包含本地模型和推理运行时，安装后无需另行下载模型。

1. 打开 DMG，将 `ztype.app` 拖入 `Applications`。
2. 从“应用程序”目录打开 ztype。
3. 如系统提示无法验证开发者，请先确认下载来源及 SHA-256 校验值。
   当前发行包使用临时签名，尚未完成 Apple 公证；只有确认信任此包时，
   才在“系统设置 → 隐私与安全性”中选择“仍要打开”。不要关闭 Gatekeeper。
4. 在 ztype 中开启跨应用补全，再按系统提示授予“辅助功能”和“输入监控”权限。
   设置中的“Tab 接管”应显示“可用”。

不要直接从 DMG 中运行或授权。更新临时签名版本可能需要重新授权；
本机开发证书签名与公开发行包的身份不同。源码仓库不包含本机证书。

## 从源码构建

需要 Swift 6 或更新的 Xcode/Command Line Tools，以及 Python 3.12 或更新版本。

```bash
git clone https://github.com/xiaohei210509/ztype.git
cd ztype
python3 script/setup_engine.py
./script/build_and_run.sh --verify
```

模型与运行时版本及 SHA-256 固定在 `Resources/runtime-assets.json`。
下载时验证校验值，不把最新上游版本悄悄替换为未经测试的版本。
运行测试不需要下载模型：`./script/test.sh`。

## 启动

已经构建的应用入口位于 `dist/ztype.app`，指向本机缓存中的运行包，
或已经安装到“应用程序”目录的运行包，避免同步目录重新附加 Finder 元数据破坏
签名。构建优先沿用 `/Applications/ztype.app`，其次为 `~/Applications/ztype.app`；
没有安装包时才使用缓存目录。`ZTYPE_APP_PATH` 可显式指定输出位置。
移动真实应用包后，开发替身需要重新指向新位置，应用注册也需刷新。
首次打开不会自动开始全局输入监控；之后保留用户的跨应用开启意愿，
重启或从系统设置返回时重新检查授权并建立监听，不进行定时权限轮询。
试写区无需辅助功能权限；跨应用模式需要点击“开启”，由用户在系统设置中
授权 ztype 的辅助功能及输入监控权限。系统可能创建非空事件监听，却移除其中的
键盘事件；只有实际注册列表包含按下、松开、修饰键及鼠标失效事件，才认为
跨应用监听已开启。没有完整键盘监听时不显示无法接受的灰色候选。
设置中分别显示辅助功能、当前进程的输入监控授权和 Tab 接管状态。

应用以菜单栏工具运行，不显示 Dock 图标。关闭试写窗口不会退出或关闭跨应用
补全；通过菜单栏的“打开 ztype”可重新打开同一个窗口，“设置…”可调整选项，
“退出 ztype”会停止输入监控及所属推理进程。首次启动仍展示试写窗口。
名称、窗口标题、应用包和菜单栏入口统一使用小写 `ztype`。

- `Tab`：接受下一个词。
- `Option+Tab`：接受整个候选。
- 继续输入或移动光标：丢弃旧候选。
- `Escape`：忽略当前候选；内置试写区会短暂抑制重新预测。
- 菜单栏开关：暂停补全。
- 月亮按钮：立即卸载模型。

逐词接受后会复核新的上下文；确认文本已正确插入后，复用候选剩余部分，
不为每一个已生成的词重新运行模型。连续按 Tab 始终依次接受最初看见的
同一条候选，不因编辑器排版暂时不可读而换一条候选。候选全部接受完后，
等待用户实际编辑文本，不自动生成下一条。继续按原生 Tab 也不会请求预测。
新的非 Tab 输入或粘贴会丢弃旧候选，
再根据光标位置的新上下文预测。
跨应用 Tab 在有可用候选时先认领按键，按下、抬起及同一次长按均不会
交给编辑器做缩进；没有候选时保持原生 Tab。文字读取与插入不在事件
监听回调中执行。认领后若校验失败，只显示失败状态，不回放 Tab 或重复写入。
按键拦截运行在独立的事件线程，只读取加锁的候选状态并向主线程投递动作；
AX 查询、剪贴板操作、排版及模型推理不会在该回调中执行。
跨应用接受使用编辑器自身的系统粘贴命令，不按软件名称逐个适配，也不再依赖
选中文字接口的成功返回值或整串 Unicode 按键注入。等待 Tab 及修饰键松开，
再次校验输入目标后才发送粘贴；插入期间再次按 Tab 会排队接受剩余词，
同一次长按不重复接受。事件发出不等于插入成功；只在
读取到预期的 UTF-16 光标推进、前文和后文后才增加接受计数或复用剩余候选。
插入确认只进行有限次短暂读取，不是后台轮询；用户键入、点击、切换应用
或移动窗口会取消待处理接受。延迟到达的自有文本通知在内容未变时不清除
剩余灰字，真实文本变化仍使候选失效。
剩余候选的位置读取有有限次布局重试，不因一次短暂的 AX 排版延迟立即丢弃。
重试仍未获得位置时只隐藏覆盖层，文本及其经过确认的输入目标继续保留，
下次 Tab 在再次核对上下文后仍可接受同一候选的下一词。后续未改变文本的
辅助功能通知可以恢复覆盖层，不会调用模型；暂时无法读取文本的通知也不
视为真实编辑。内置试写区同样区分自有插入通知与用户编辑。
粘贴会短暂使用剪贴板：原项目及数据格式仅在内存中保管，确认后恢复；
取消或确认超时会延迟恢复，让已发送的粘贴有机会读取。期间用户复制了新内容时
不会覆盖新剪贴板。无法完整保管或超过 8 MiB 时拒绝这次插入，不破坏原剪贴板。
正常退出时如仍有待恢复的剪贴板，会短暂延迟退出以完成恢复；强制杀进程或系统
崩溃无法保证恢复，不能把临时剪贴板租用描述成完全不触碰剪贴板。
接受阶段日志仅记录提交、确认及失败原因，不记录正文、候选或剪贴板内容。

没有候选时不拦截 Tab；任何候选都不会自动写入文档。试写区没有自动纠错、
引号替换或文字替换。输入内容不保存到配置或日志。

## 构建与测试

```bash
./script/build_and_run.sh --verify
./script/test.sh
swift script/verify_app.swift --running --project-entry
swift script/verify_app.swift --running --keyboard-monitor
./script/build_and_run.sh --print-app-path
python3 script/benchmark.py
```

新机器缺少推理资产时：

```bash
python3 script/setup_engine.py
./script/build_and_run.sh --verify
```

安装器从 llama.cpp 官方 GitHub 发布和 Qwen 官方模型仓库下载独立资产，
验证 SHA-256 后才使用。模型约 1.83 GB。来源版本和校验值记录在
`Resources/runtime-assets.json`；安装后也写入
`Runtime/runtime-version.json`、`Runtime/model-version.json`。
当前模型为 Qwen3-1.7B-Q8_0（Apache-2.0），运行时为 llama.cpp。
下载只发生在安装阶段，补全时仅访问本机随机端口。

构建缓存默认位于 `~/Library/Caches/ztype/Build`，避免云同步目录的
Finder 扩展属性干扰测试签名。`ZTYPE_BUILD_DIR` 可指定其他构建缓存路径。
本机工具链无法找到 XCTest 启动器，所以测试使用 Swift Testing。

图标源图为 `Resources/AppIcon.png`，应用图标为 `Resources/AppIcon.icns`。
运行 `./script/build_icon.sh` 可从源图重新打包所有标准尺寸；普通构建直接
复制已打包的图标。生成方式与提示词见 [图标记录](docs/app-icon.md)。

## 权限排查

权限列表添加应用没有反应时，先核对实际应用包的位置、签名和应用注册，
不要先重置系统权限数据库。运行中移动应用可能让权限服务继续引用旧位置。
退出应用、刷新新位置的 Launch Services 注册后再从新位置打开。
`dist/ztype.app` 是开发替身，授权时应选择实际安装包。开发暂存包不能与正式
安装包同时作为同一个 Bundle ID 的有效注册入口。
构建优先复用已安装包的签名证书；第一次构建时如只有一个有效 Apple Development
或 Developer ID Application 身份，则使用它。也可通过 `ZTYPE_SIGNING_IDENTITY`
指定证书。原证书不可用时拒绝静默降级签名。没有明确证书时仍可临时签名，
但会提示每次重编译可能需要重新授权。
临时签名的授权绑定代码哈希，换版本后系统开关可能仍显示开启，实际权限却拒绝
新进程。迁移到证书签名需要用户对新版本重新授权一次；之后同一证书与 Bundle ID
的正常更新可保持签名身份。不会改写 TCC 数据库、重置权限或自动切换系统开关。
签名仅用于本机开发运行，不表示已公证或完成商业发行验证。

## 上下文与安全

只读取当前聚焦输入框的光标前最多 1,800 个 UTF-16 单元和光标后最多
320 个 UTF-16 单元，不读取其他窗口、剪贴板或截图。系统辅助功能读写
设有超时；按编辑器公开的辅助功能能力选择读取方式，不按应用名称设置
支持白名单。标准 UTF-16 范围优先，富文本范围和编辑器公布的文字标记
接口作为备用；文字标记保持不透明，不调用私有框架或解码其内存。
无法确认文本范围或光标定位时仍暂停补全，不猜测插入位置。
文末零长度 AX 范围在部分 AppKit 输入框中可能返回偏移一行的位置；
对于非换行结尾的左到右文本，使用前一个完整字符的范围恢复插入点。
仍检查可见区域，不根据鼠标位置猜光标，也不通过截图读取文本。
富文本保留隐含段落结束符时，文末光标不一定等于全文字符数量；若零长度
坐标不可用且后文以换行符开头，可从前一个完整字符恢复行末插入点。
焦点为布局容器时，只在该聚焦子树内进行有界搜索，要求明确聚焦或唯一
可编辑候选，不搜索整个窗口来任选一个文本框。缺失自身边框时，从所属
滚动区和窗口确定可见范围。

生成前、显示前、插入前分别核对输入框、光标、选择范围和上下文。
键入、点击、滚动、应用切换及确认了真实文本变化的辅助功能通知会使候选失效；
自有插入的延迟通知或未改变上下文的通知不会清除候选。
输入源切换、窗口移动和缩放也会清除已有候选。
跨应用读取失败会显示具体原因（权限、聚焦输入框、文本范围、字符计数、
光标位置或可见区域），并注明捕获时的应用名称，不再统一显示“等待可用上下文”。
短暂布局失败仅在停止输入后重试一次，120 ms 内有新输入或应用切换则取消，
不增加定时后台轮询。内置试写区不经过
跨应用 AX 读取，因此其可用不代表某个第三方输入框已兼容。
默认跳过密码框、终端和常见密码管理器，并支持追加应用 Bundle ID 排除项。
候选通过长度、重复前缀、元回复及格式检查。
现在采用开放续写：允许猜测天气、数字、日期、原因及时间承诺，不因为这些
细节尚未出现在原文中而过滤。`because` 后也可以继续预测。

这不是事实验证器。候选是对用户接下来可能输入内容的猜测，不是已经核实的
事实。过滤保留长度、重复、元回复和格式检查，并非已校准的准确率或置信度。
上下文仅来自当前输入框，因此不会知道用户未写出的背景、真实意图或其他
文档内容。仍需由用户判断是否接受。

## 性能与能耗

| 策略 | 停顿等待 | 请求最短间隔 | 生成预算 | 空闲卸载 |
| --- | --- | --- | --- | --- |
| 响应优先 | 160 ms | 300 ms | 16 tokens | 90 秒 |
| 均衡 | 260 ms | 500 ms | 16 tokens | 90 秒 |
| 节能 | 480 ms | 900 ms | 12 tokens | 30 秒 |

客户端使用 llama.cpp 原生续写协议，不再依赖聊天接口把已写文本回填到
回答中的行为。提示词通过完整草稿示例说明补全任务，再从光标位置续写。
用户文本以普通 tokens 编码，不能被解析成聊天角色分隔符。英文词尾通过
字面前缀约束重生成最后一个 token，只返回尚未输入的部分，不改动已写文本。
根据当前行的语言选择缓存模板；英文模板只放英文示例，并使用同一次生成
的字符约束防止汉字串入，展示前再校验。数字、日期、符号及重音字母仍可
生成；中文或混合草稿不套用英文限制。输入源语言作为无语言线索时的参考。
遇到句末标点提前停止；固定提示词的 tokenization 结果在本次进程内复用。
光标后的重复文本会从候选中去除，而不是整条丢弃。总提示词超出服务端
上下文预算时跳过，不让服务端悄悄移除重要上下文。

推理服务只启用一个生成槽，限制上下文为 2,048 tokens、CPU 线程为 3，
开启 Metal 加速并关闭忙轮询。客户端会取消失效请求，服务端的单槽和
短输出预算限制重叠生成。低电量模式强制节能，严重热状态暂停，
睡眠或会话失活时卸载模型。没有定时上下文轮询，也没有后台学习或上传。
服务端另有 90 秒空闲模型卸载保险；正常退出及开发重启会停止所属推理进程。

界面的延迟统计仅计本地请求到返回，不包括去抖、模型冷启动或 AX 查询。
`benchmark.py` 使用合成句子并输出模型加载、推理分布和空闲 CPU 样本，
不读取用户文档。CPU 样本不能替代 GPU/整机功耗及电池续航测量。
可加 `--output Benchmarks/integrated-completion.json` 保存原始输出、实际
显示内容和请求延迟。原始输出条数和显示候选数量都不是准确率。

## 初版边界

- 原生试写区与跨应用模式都以光标后的灰字预览候选，并且只在用户显式接受
  后写入。跨应用通过透明、无阴影的非激活覆盖层绘制，不改写第三方文档。
  优先采用光标前文字的 AX 字体，字体不可读时按光标高度估算。覆盖层裁切
  到输入框、滚动区、窗口与屏幕的可见范围；同一行已有后文时暂停显示，
  避免遮住用户内容。它仍是外部覆盖层，不等同于第三方编辑器自身的文本布局。
- 中文或其他组合输入法启用时，跨应用模式保守暂停，以免抢走候选确认键。
  内置试写区能识别 marked text，提交后才运行预测。
- 短中文前缀从四个汉字起允许预测。提示模板按草稿语言隔离示例；纯英文
  草稿中的汉字候选会被丢弃，中文及中英混合草稿不使用该过滤。真实组合
  输入和不同第三方控件仍需逐一验证，不宣称完整兼容。
- 读取层包含标准范围、富文本范围和文字标记备用路径；这并非逐个应用的
  兼容性证明。Pages、浏览器富文本、Google Docs、代码编辑器及其他自绘
  输入框仍需要完整输入、显示、接受、滚动与光标移动实测。
  默认不会对不可靠输入框强行回写。
- 暂未提供自动更新、登录项或公证。构建可使用本机已有开发证书。这是本机原型，
  不应作为已验证的商业成品发布。
- 模型卸载后的第一条补全需要重新加载；节能与冷启动速度存在明确取舍。
